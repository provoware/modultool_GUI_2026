# Release-Ziel (Back-to-Front)

Wir planen „von hinten nach vorne“:

## Definition „Releasefertig“
1. **Start**: Ein-Klick, Port-Fallback, klare URL, kein Crash
2. **Core**: Preflight + Self-Repair + saubere Logs
3. **UI**: 2×2 Raster, keine Überdeckung, responsive, Themes & Accessibility wirksam
4. **Snippets/Macro-Keys**: CRUD + Clipboard + History, sofort sichtbar, geloggt
5. **QA**: Verhaltenstests (HTTP/FS/Negativfälle) + CI grün
6. **Distribution**: ZIP + (optional später) Desktop-Entry / .deb

## Aktuelle Leitplanke
Wenn etwas unsicher ist: Feature weg lassen, Robustheit rein.
